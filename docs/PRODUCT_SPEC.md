# Curio 产品要求与交付核对

这份记录把 Curio 建站以来的对话决策、当前实现和操作边界集中在一起，后续修改以它和代码为准。

## 产品定位

- 网站：<https://curio.wiki-power.com>
- 仓库：<https://github.com/linyuxuanlin/curio>
- 托管：Cloudflare Pages，生产分支为 `main`。
- 内容：真实、有来源、适合一张图讲清的世界趣闻。
- 内容任务：ChatGPT 任务“Curio 每小时维护”每小时生成 5 张新卡片，并推送到 GitHub。任务必须保持启用；代码开发与视觉修改先在本地完成，再推送 GitHub。
- 不发送邮件，不调用 Gmail。网站不需要登录、数据库或运行时 API 密钥。

## 已确定的交互

- 首屏优先展示新生成且未读的卡片。
- 卡片为竖向标准信用卡比例，宽高约 `0.63:1`；移动端尽量占满可用宽度，短屏时等比例缩小。
- 正面只放图片、标题和简要；底部有小字“点击卡片翻面”。
- 点击整张卡片时，整张卡片通过 3D 拟物翻面；背面放详细内容、来源和图片署名。
- 鼠标、触屏和键盘左右键都支持向任意方向划走；下一张卡片在当前卡片离场的同时自然就位，动画支持连续快速操作。
- 两个操作按钮为底部宽胶囊按钮，不遮盖初始卡片；卡片拖动时可以覆盖按钮区域。
- 页面、卡片和卡片内容不出现纵向或横向滚动条。
- 读完全部未读卡片后显示“已读完”，播放一次烟花，并提示“每小时更新 5 张新卡片”。“手气不错”可随机掉落历史卡片，但排除本次会话和最近 30 分钟刚读过的卡片。
- 已读记录保存在当前浏览器 `localStorage`，跨刷新保留；不同设备不互通。撤回会恢复之前的已读状态。
- 网站支持 PWA：桌面/Android 可使用浏览器安装入口，iPhone 可用“分享 → 添加到主屏幕”；Service Worker 对 feed 使用网络优先，对静态资源使用缓存优先。

## 内容与图片规则

- 每小时 5 张卡片必须是 5 个不同事件，跨领域轮换；最近 6 期天文/航天最多 1 期，除非有明确重大理由。
- 优先过去 24–72 小时内的事件；扩大日期范围时写入 `verificationNotes` 并设置 `archive: true`，不能改事件日期伪装新鲜。
- 每张卡片至少 2 个、最多 4 个可靠来源，关键事实尽量由两个独立来源交叉核实。
- 每张卡片必须有图片。真实图片记录来源、作者和授权限制；生成图片只能使用 GPT Image 2.5，并标注 `kind: generated`、`model` 和 `visualChecked`。
- 原图只允许裁剪、缩放、留白、边框和文字排版，不改变现场事实。没有合格图片时换题或重试，不发布无图卡片。
- 不重复事件；转载、翻译或换标题不算新事件。不得为了凑够 5 张降低核验标准。

## 发布流程

1. 本地开发时先读取 README、架构、内容格式和本文件。
2. 每轮内容新增 5 个 JSON 和必要图片；代码修改也必须在本地验证。
3. 运行 `npm run validate`、`npm test`、`npm run build`。
4. 推送 GitHub `main`，Cloudflare Pages 自动构建。
5. 检查部署状态，并请求线上 `/feed.json`；5 个 ID 和图片都在线后才报告已发布。
6. 不提交 `public/feed.json`、`dist/`、`node_modules/`、密钥或临时图片。

## 当前状态与限制

- 首批内容已入库 6 张；内容数量会由每小时任务继续增长。
- 当前自动化任务已启用；不要再创建同名或重复任务。
- 网站是静态前端，阅读记录只在浏览器端保存，没有账号体系和跨设备同步。
- Service Worker 首次安装后会缓存应用外壳；新 feed 仍优先走网络，离线时回退到最近一次缓存。
- Cloudflare Pages 的构建和自定义域名传播可能有短暂延迟；最终验证以线上 `feed.json` 和部署状态为准。
