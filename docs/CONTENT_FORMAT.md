# 内容格式

每个事件一个 UTF-8 JSON 文件，路径 `content/cards/<id>.json`。参考仓库内真实卡片。普通编辑只新增文件，不维护聚合索引。

| 字段 | 说明 |
| --- | --- |
| `id` | 永久 ID，小写英文数字和连字符；文件名必须与它一致，不因修正标题而变化。建议 `YYYY-MM-DD-英文主题`。 |
| `eventKey` | 跨新闻转载、语言和标题的稳定事件标识；同一研究 DOI、公告或活动只允许一个。 |
| `category` | 科技、AI、机器人、交通、工程、动物与自然、城市生活、设计、文化、考古、食品、环境、社会、天文/航天之一。 |
| `title` | 36 字以内的短标题，不含“趣事”，建议 2 行；可用 `\n` 明确换行。界面提供领域，不必重复“趣闻｜”。 |
| `summary` | 100 字以内，一个结论加一句补充，不写新闻稿式长句。 |
| `body` | 1–2 段纯文本字符串，每段最多 80 字，总计最多 140 字（含标点、空格及英文字符）。只补充必要背景，不重复正面的标题和简介；来源及图片署名放在各自字段，不占正文。 |
| `eventDate` | 事件发生/研究公布日期，带时区 ISO 8601；如果来源仅提供日期，可统一记当天 12:00 UTC，并在核查说明注明日期精度。不要从文章更新日倒推事件时间。 |
| `publishedAt` | 本站实际入库时间，带时区 ISO 8601。决定未读排序，不可用于伪装旧闻。 |
| `verifiedAt` | 实际完成事实核查时间。 |
| `location` | 简短地点；无法确认就写确实能确认的地区，不推断现场。 |
| `sources` | 2–4 个 `{ "name": "机构或媒体名", "url": "https://..." }`；可点击到对应报道或论文，不能用搜索结果页。 |
| `verificationNotes` | 核实过的关键事实、日期精度、来源独立性、局限和图片选择依据。公开字段，不放秘密。 |
| `theme` | sage / clay / blue / gold / plum，控制领域标签颜色。 |
| `archive` | 是否往期精选；超过 72 小时的扩展选题通常为 true，并解释扩展原因。 |
| `image` | 每张卡片必填图片对象；优先真实原图，没有合适原图时使用 GPT Image 2.5 示意图。 |

图片字段示例（模板中的链接与文件名必须替换为真实核实过的值，不可直接发布）：

```json
{
  "src": "/media/unique-event-id.webp",
  "alt": "真实、准确的图像描述",
  "credit": "摄影师 / 机构",
  "sourceUrl": "https://example.org/original-news",
  "license": "具体的复用许可与限制",
  "licenseUrl": "https://example.org/reuse-policy",
  "kind": "original",
  "layout": "photo"
}
```

`layout: "photo"` 会适度裁切填充；带文字海报、对照图或不能裁掉事实/署名的图必须用 `"poster"`，完整显示。生成图另需 `"kind": "generated"`、`"model": "GPT Image 2.5"`、`"visualChecked": true`，前端自动添加“示意图 · 非现场照片”。`sourceUrl` 和 `licenseUrl` 必须记录真实的生成/使用依据；不可编造链接。生成图片无法满足规范时，必须继续寻找或生成合格图片，不能发布无图卡片。

不允许 HTML、脚本、内联 SVG、data URL、临时会话文件链接或本机文件路径。上传本地图片后，`src` 从 `/media/` 开始，不含 `public`。图片与 JSON 要原子提交，避免出现空图。

`npm run validate` 检查结构、重复、URL、日期和本地文件存在性；它不等于事实核实，也不会证明来源可靠或授权有效，这些仍需内容发布者实际检查。
